Robots.txt utilities

Components for handling robots.txt rules:

  • Parsing Crawl-delay directives
  • Fetching and caching robots.txt rules with a TLS-fingerprinted client
  • Checking URL permissions

The RobotsFetcher owns a shared wreq::Client built with the caller’s TLS/HTTP2 emulation profile (#337). Previously robots.txt was fetched with a bare wreq::get(), which spun up a throwaway client carrying the default TLS fingerprint — a bot signal for WAFs that compared it against the main page downloader’s fingerprint. Routing the fetch through an emulated client keeps the robots.txt fingerprint consistent with the rest of the crawl.
