# Fix release artifact authenticity, token scoping, advisory governance, and SBOM

Issue: #1607 — release artifacts are unsigned, non-reproducible and published with write-capable tokens.
Worktree: `/home/xavi/Projects/Rust/webfang-worktrees/fix-release-artifact-signing` · Branch: `fix/release-artifact-signing`

## Problem

The release pipeline publishes artifacts with no cryptographic authenticity (a
`SHA256SUMS.txt` generated by the same job that built the binaries proves nothing),
a Markdown table passes for a provenance attestation, an annotated tag is treated as
an auth boundary, advisory governance is a hand-maintained allowlist with no expiry
and no enforcement, and the advisory gate is duplicated in two places that have
already drifted.

## Why keyless, and what that buys

Long-lived signing keys need a maintainer-held secret, which cannot be provisioned
here. **Keyless** (sigstore/cosign + GitHub OIDC) needs no secret: the signing
identity is the workflow file + ref, the certificate comes from the Actions OIDC
issuer, and the trust anchor is the public Rekor transparency log. That is the only
authenticity design that can actually be landed without out-of-band provisioning —
and it is strictly stronger than what the pipeline has today (nothing).

The cost is honest and must be documented: the identity is a *workflow path*, not a
person, so the trust boundary is "this workflow, at this ref, in this repo, signed
during this run" — bound to the tag by the release job's own inputs and pinned by the
consumer's `--certificate-identity` regex.

## Acceptance criteria

1. A consumer can verify a published archive's authenticity without trusting the job that built it: `cosign verify-blob --bundle <asset>.sigstore.json --certificate-identity … --certificate-oidc-issuer … <asset>`, and the same for `SHA256SUMS.txt`.
2. The GitHub Release carries a real SLSA provenance attestation, not a Markdown table.
3. `publish` refuses to create a release when any asset signature is absent, invalid, or from a foreign identity.
4. Every `uses:` is SHA-pinned **and** `unpinned-uses` is enabled, so the next unpinned `uses:` fails the build.
5. A new unmaintained/unsound/yanked advisory fails `cargo deny check` **and** `cargo audit`, in both the root and fuzz lockfiles.
6. Every advisory ignore carries a justification, an explicit expiry, and a unique id; a past expiry fails.
7. `persist-credentials: false` on every checkout; zizmor still runs in CI; the tag ruleset still blocks update/delete; `cargo deny check` passes for licenses/bans/sources; no SSPL/AGPL/standalone-GPL expression; the BoringSSL advertising clause stays absent.
